# 연재 결정 기록과 다음 작업

정리 기준일: 2026-10-19. 이 문서는 대화에서 정한 방향과 다음 작업을 기록한다.

## 확정된 방향

- 자체 개발한 비행 시험 데이터 플랫폼을 기반으로 기술 블로그를 운영한다.
- 개발 배경과 외부 기술 의존으로 생긴 확장 제약을 설명한다.
- 어떤 서비스를 제공하며 왜 필요한지 설명한다.
- React, FastAPI, PostgreSQL의 선택 이유는 각각 한 편에서 다룬다.
- 개념을 깊게 공부하기 위해 이론 하나당 한 편을 구성한다. 편수 상한은 두지 않는다.
- 기존 개발기와 이론 학습을 연결한다. 기능별 개발 글 뒤에 관련 이론 글을 배치한다.
- 여러 선택지와 요구사항을 비교하고, 선택의 근거·비용·검증·한계를 설명한다.
- 사용자 수정 원고를 기준으로 문체를 유지한다.

## 기획 변화

1. 개발 배경, 서비스, 아키텍처, 기술 선택, 기능 개발, 성능·검증을 다루는 개발기 기획.
2. 코드 검토를 통해 적용한 CS 개념을 정리.
3. 도입·기술 선택 4편과 이론 56편을 묶은 60편 학습 초안 제안.
4. 이론만 나열하면 개발 흐름이 약해지는 문제를 반영해 개발 글 16편과 이론 56편의 72편 통합 목차 제안.
5. 영상에서 사용자가 짚은 선택 근거 설명 방식을 글 작성 원칙에 반영.

기존에 독립 게시할 필요가 없다고 판단한 데이터 특징·서비스 소개는 해당 개발 글의 도입에 포함한다. 72편은 작성할 때 조정할 수 있는 기획 순서이며 원고 완성 수가 아니다.

## 현재 계획과 다음 작업

- 02-1: React 소개·핵심 개념·도구 선택 기준·대안 비교·플랫폼 적용 이유. 최신 분할 초안은 `posts/02-1-react.md`.
- 02-2: React와 함께 사용하는 도구. Vite, React Router, Recharts, Tailwind CSS, Lucide React 및 CSS·호환·검사 도구의 역할.
- 02-3: 선택에 따라 관리해야 하는 부분. 상태 설계, 비동기 응답, 의존성, 빌드와 폐쇄망 배포.
- 이후 선언형/명령형 UI 코드 비교, 컴포넌트 연결과 state/props, 상태 분류, 단방향 데이터 흐름과 양방향 바인딩을 개념별 학습으로 이어간다.
